我把仓库当前 `master` 的 Wiki 数值体系完整走了一遍。先说结论：

**这套游戏的数值框架是成立的，但目前不建议直接进入“逐把刀微调攻击力”的阶段。** 当前真正影响平衡的不是 6 攻还是 7 攻，而是有几处 **P0 级底层规则互相打架**。如果先调刀，后面改公式/羁绊/掉落时会全部推翻。

另外目前仓库主体还是设计 Wiki，根目录只有 `docs-wiki` 和规划文档，还没有可运行战斗代码，因此下面属于**设计层数值审核 + 数学静态校验**，还不是实际 Monte Carlo 战斗结果。([GitHub][1])

# 一、目前我认为最需要先修的 7 个问题

| 优先级 | 问题                 | 当前表现                | 风险             |
| --- | ------------------ | ------------------- | -------------- |
| P0  | 速度增伤方向反了           | 重刀更容易吃满 +50%        | 重刀二次膨胀         |
| P0  | 羁绊全阵增益             | 低重量刀会沦为 buff 挂件     | 最终只有“挂件+主C”    |
| P0  | Build 示例实际无法触发羁绊   | 火/毒/雷/玄都有错误         | Wiki 无法作为权威数据源 |
| P0  | 声望奖励直接跳进度          | 打 2 个 Boss 可能直接开域4  | 成长节奏崩溃         |
| P0  | 金币/掉刀按敌人数结算        | 后期一波几十只怪导致经济爆炸      | 后期资源失控         |
| P1  | Boss 血量和目标 TTK 不匹配 | 理论几十秒结束，目标却是 2–4 分钟 | Boss 没阶段感      |

下面几个值得单独解释。

# 二、P0：相对速度增伤公式实际上在奖励重刀

现在公式是：

`速度增伤 = clamp(v_rel / 30, 0, 0.5)`

最高 +50%。([GitHub][2])

而公转产生的线速度大致是：

`v = 2π × 公转速度 × 半径`

拿现有刀表直接算：

| 刀    | 重量 |  公转 |  半径 | 仅公转产生的线速度 |     当前速度增伤 |
| ---- | -: | --: | --: | --------: | ---------: |
| 柳叶刀  |  1 | 0.6 | 2.5 |      9.42 |       +31% |
| 飞蝗刀  |  1 | 0.7 | 2.5 |     11.00 |       +37% |
| 燕翎刀  |  2 | 0.7 | 3.2 |     14.07 |       +47% |
| 断骨刀  |  3 | 0.6 | 4.0 |     15.08 | **+50%封顶** |
| 惊雷刃  |  4 | 0.6 | 5.0 |     18.85 |   **+50%** |
| 镇岳刀  |  5 | 0.5 | 6.0 |     18.85 |   **+50%** |
| 百炼青霜 |  5 | 0.9 | 6.0 |     33.93 |   **+50%** |

刀的原始公转、半径数据在这里。([GitHub][3])

所以文档里“**轻刀高速天然吃相对速度加成，是 1 斤刀隐藏补偿**”这个设计目标，数学上没有实现。([GitHub][2])

反而是：

**半径越大的重刀 → 线速度越高 → 更早吃满 +50%。**

这应该是第一处改动。

### 我的建议

不要再用“实际线速度”直接决定这么大的伤害乘区。

v1.3 可以先改成：

```text
速度伤害加成 =
clamp(
  (spin / 1.5 - 1) × 0.16
+ (orbit / 0.6 - 1) × 0.12
+ 玩家有效移动速度 / 6 × 0.08,
-0.10,
+0.30
)
```

核心变化是：

**不再让 R 公转半径直接产生伤害收益。**

半径本身已经是非常强的属性——它提高覆盖面积、安全距离、多目标命中能力，再额外转换为伤害属于“一项属性吃两个乘区”。

同时把速度乘区上限从：

**+50% → +30%**

会健康很多。

# 三、P0：羁绊现在极容易演化成“挂件系统”

当前规则规定，2 件和 4 件羁绊都是**作用全阵**。例如：

* 风2：全阵公转 +25%
* 火2：全阵攻击 +12%
* 雷2：全阵暴击 +10%
* 刚2：全阵攻击 +18%

([GitHub][4])

与此同时，你的阵容唯一真正预算是**负重**，没有刀位成本；终局负重达到 36。([GitHub][5])

这会出现一个非常典型的最优解：

> 1斤/2斤刀负责“开羁绊”，5斤橙刀负责吃所有羁绊。

最后玩家不是在玩“风流、刚流、火流”，而是在算：

**用最低几斤重量买到多少个全阵 buff。**

尤其火2 + 刚2：

`1.12 × 1.18 ≈ 1.32`

两个羁绊已经给主 C 约 **32% 乘算攻击收益**。

再叠雷2、风2，混色挂件基本必然优于纯系构筑。

### 建议改成“主系收益，少量全阵收益”

例如：

| 羁绊 | 当前             | 建议                   |
| -- | -------------- | -------------------- |
| 风2 | 全阵公转 +25%      | **风刀**公转 +20%，全阵 +5% |
| 火2 | 全阵攻击 +12% + 灼烧 | **火刀**攻击 +10%，火刀附灼烧  |
| 水2 | 全阵冰缓           | **水刀**命中附冰缓          |
| 毒2 | 毒层 5→7         | 基本保留                 |
| 雷2 | 全阵暴击 +10%      | **雷刀**暴击 +12%        |
| 刚2 | 全阵攻击 +18%      | **刚刀**攻击 +15%        |

4 件套再允许出现少量“改变全阵规则”的效果。

这样纯系的收益会明显高于“挂两个开 buff”。

# 四、现在 6 套 Build 里有多处硬错误

这里不是平衡问题，是规则一致性问题。

例如当前定义明确写着：

**达到同系 2 把才触发 2 件套；玄系不参与件数。** ([GitHub][4])

但是 Build 表里：

* 烈焰环学徒：`火褶×1 + 柳叶×2 + 青竹`，只有 **1 把火刀**，却写“火2”
* 蚀骨毒环：`蜈蚣×1 + 寒月 + 柳叶×2`，只有 **1 把毒刀**，却写“毒2”
* 惊雷九霄：`惊雷×1 + 柳叶×3`，只有 **1 把雷刀**，却写“雷2”
* 惊雷刀圣：`惊雷×2`，却写成“雷4”
* 两仪归一写“玄2”，但规则又明确写着**玄系没有羁绊位**

([GitHub][6])

另外：

`柳叶×2 + 飞蝗 + 青竹`

四把都是 1 斤，实际 **4斤**，表里写成了 5 斤。([GitHub][6])

### 这里我反而建议做一次更大的调整

你的 14 把刀中系别分布是：

**风4 / 火2 / 水1 / 毒1 / 雷1 / 刚3 / 玄2**。([GitHub][3])

所以“所有属性统一 2/4 件套”其实并不适合当前内容量。

尤其雷刀只有一种，雷4意味着玩家必须带：

**惊雷刃 ×4 = 16斤**

名匠只有 15 斤负重，理论上都不可能成型。([GitHub][5])

我建议二选一：

**方案 A，推荐：新增低重量水/毒/雷刀。**

让每个主流系至少拥有：

`1斤 + 2斤 + 3~4斤核心`

这样才能真正做自走棋式 2/4 构筑。

或者 MVP 阶段采用：

**风/刚 2-4，火 2-3，水/毒/雷 1-2**

但规则会稍微不那么漂亮。

我更偏向 A。

# 五、声望成长目前会严重“跳级”

现有门槛：

| 目标 |   声望 |
| -- | ---: |
| 域2 |  100 |
| 域3 |  250 |
| 域4 |  500 |
| 域5 |  900 |
| 至尊 | 1500 |

([GitHub][7])

但 Boss **首次击杀**奖励是：

| Boss |  首通声望 |
| ---- | ----: |
| 域1   |  +200 |
| 域2   |  +350 |
| 域3   |  +500 |
| 域4   |  +750 |
| 域5   | +1500 |

([GitHub][8])

只算 Boss：

```text
打完域1：200
打完域2：550
打完域3：1050
打完域4：1800
```

也就是说：

**打完域2，你已经超过域4的 500 门槛。**

甚至还没算：

* 普通敌人 +1
* 节点 +5
* 精英 +10
* 事件 +50~200

([GitHub][7])

所以现在“域1→域2→域3→域4→域5”的成长路径实际上会被声望系统自己绕开。

### 推荐 Boss 首通声望

我建议先改成：

| 域 |       首通 |   重复 |
| - | -------: | ---: |
| 1 |  **+60** |  +20 |
| 2 |  **+90** |  +30 |
| 3 | **+150** |  +50 |
| 4 | **+250** |  +80 |
| 5 | **+350** | +120 |

然后保留普通怪、节点、事件声望。

设计目标变成：

> 正常打完一整个域 ≈ 刚刚触及下一域门槛。

比现在 Boss 一只怪直接送两三个阶段健康得多。

# 六、经济系统现在最大的问题不是价格，而是“按怪发钱”

当前明确写了：

> 每域金币预算约 40–70 金。([GitHub][9])

但域4的一种普通波次是：

`马贼骑×4 + 重甲卫×2`

每只都掉 **4–6 金**。([GitHub][10])

所以：

```text
一波：
6只 × 4~6金 = 24~36金

域4一个战斗节点：
3波 = 72~108金
```

**一个普通战斗节点就已经超过“整个域40–70金”的预算。**

域5更严重。

刀傀单只：

* 5–8 金
* 10% 紫刀
* **5% 橙刀**

([GitHub][10])

一个普通域5节点可能：

`6刀傀 × 3~4波 = 18~24只`

至少出一把橙刀的概率大约是：

```text
1 - 0.95^18 ≈ 60%

1 - 0.95^24 ≈ 71%
```

也就是说所谓“橙色终局刀”，到了域5普通战斗节点，实际上是**六七成概率掉一把**。

这会彻底摧毁三合一、Boss 掉落和锻造价值。

## 我建议直接换奖励模型

**不要再让每只小怪独立掉金币和高品质刀。**

改为：

`怪物 → 战斗表现`

`战斗节点结算 → 金币/材料/刀`

例如：

| 域 | 普通节点金币 | 精英金币 | 普通刀掉率          | 精英刀掉率          |
| - | -----: | ---: | -------------- | -------------- |
| 1 |      8 |    — | 10% 白          | —              |
| 2 |     10 |   18 | 12% 绿          | 25% 绿          |
| 3 |     12 |   22 | 15% 蓝          | 30% 蓝          |
| 4 |     14 |   26 | 15% 蓝 / 5%紫    | 30% 紫          |
| 5 |     16 |   30 | 20%紫 / **2%橙** | 40%紫 / **8%橙** |

Boss 继续保底给刀。

这样有三个好处：

**怪越多 ≠ 钱越多；AOE 流派不会因为杀怪数获得额外经济；波次数值以后可以随便调，不会同时把金币系统炸掉。**

# 七、Boss 血量和你的 DPS 自检表也没有对上

你的目标明确写：

> Boss 战健康区间 2–4 分钟。([GitHub][2])

终局预期 DPS：

**250–400。**

剑无极：

* 3800 HP
* 60 armor

([GitHub][8])

60 护甲按现有公式是：

`60 / 160 = 37.5% DR`

所以有效血量约：

`3800 / 0.625 ≈ 6080`

哪怕按较低 250 DPS：

`6080 / 250 ≈ 24 秒`

即使假设因为走位、无敌阶段等只有 **50% 输出 uptime**：

也就约 **49 秒**。

距离 2–4 分钟仍然非常远。

实际上我觉得这里不是简单把剑无极加到 20000 HP 就完事。

因为这个游戏的战斗操作只有走位，Boss 如果真的打 4 分钟，很容易重复。

### 我建议重新定义 Boss TTK 红线

| Boss |       建议正常首通 |
| ---- | -----------: |
| 域1   |       60–80s |
| 域2   |       70–95s |
| 域3   |      80–110s |
| 域4   |      90–125s |
| 域5   | **110–150s** |

然后通过：

**血量 + 阶段机制 + 输出窗口**

一起达到目标，而不是纯堆 HP。

普通节点则控制在：

**25–45 秒**

精英：

**40–70 秒**

这样整局节奏会紧很多。

# 八、稀有度系统必须先统一数据定义

这里目前也有明显冲突。

文档一处说：

> 每把刀都有白→绿→蓝→紫→橙路径，重量和稀有度正交。([GitHub][9])

但权威刀表本身又直接把：

* 柳叶 = 白
* 燕翎 = 绿
* 断骨 = 蓝
* 惊雷 = 紫
* 镇岳 = 橙

写成固定字段。([GitHub][3])

锻造文档又同时出现：

> 粗锻白 / 细锻绿 / 精锻蓝 / 大师锻紫 / 传说锻橙

但紧接着又说：

> **锻造产出固定白阶起步。**

([GitHub][11])

这三套定义不能同时成立。

## 推荐的数据结构

刀种数据：

```text
weapon_type
- baseAtk
- weight
- spin
- orbit
- radius
- trait
- unlockDomain
- affixPool
```

玩家实际拥有的刀：

```text
weapon_instance
- weaponId
- rarity
- affixes[]
```

也就是说：

**“惊雷刃是紫刀”取消。**

改成：

**“惊雷刃在域3解锁，掉落时最低/常见品质为紫”**

但惊雷刃本身仍然允许存在蓝、紫、橙实例。

这样三合一才是真的核心系统。

# 九、我建议的 v1.3 数值优化 Plan

### Phase 1 —— 先修规则，不调刀

先完成 5 件事：

1. 稀有度改为实例属性；
2. 修正所有 6 套 Build 的件数/重量；
3. 羁绊从“全阵大 buff”改为“主系 buff”；
4. 改掉相对速度增伤公式；
5. 金币/装备掉落从“每怪”改为“节点结算”。

**这个阶段不要改 14 把刀的攻击力。**

---

### Phase 2 —— 建立真正的“战力预算”

以后不要用单纯 `atk` 比刀。

每把刀都算几个指标：

```text
ST-DPS       单体持续输出
AOE-DPS      3目标输出
Coverage     覆盖能力
Control      控制价值
Survival     防御/回血价值
WeightEff    单位负重收益
```

核心校验标准：

> 同稀有度、同阶段下，普通刀的 WeightEff 控制在中位数 ±15%。

机制刀允许：

**±20~25%**

但超出的部分必须能明确解释，比如：

* 玄铁专门破盾；
* 血饮降低输出换续航；
* 镇岳降低敌人输出；
* 青霜牺牲单体换覆盖。

这时候才能真正判断 60 攻镇岳到底是不是高。

---

### Phase 3 —— 对乘区设硬红线

建议统一：

```text
单条普通词缀收益：8%~15%
紫词缀：12%~18%
专属词缀：15%~25%

2件羁绊：
总战力提升 ≈ 12%~18%

4件额外收益：
≈ 18%~25%

完整单系羁绊：
控制在 +35%~45%

属性克制：
1.20 / 0.85
```

我会把当前的：

**1.30 / 0.80**

稍微收一点。

因为这是一个 Roguelike，玩家可能因为随机掉落没法及时换系；`1.30 ÷ 0.80 = 1.625`，正确答案和错误答案之间已经差 **62.5%**，再叠护甲、羁绊，很容易出现“不是难，是根本打不动”。

---

### Phase 4 —— 重做成长曲线

目前：

`6 → 10 → 15 → 21 → 28 → 36斤`

其实我觉得这条曲线本身很好，不建议大改。([GitHub][5])

但 DPS 目标建议调整得更平滑：

| 境界 |  当前 DPS |        建议目标 |
| -- | ------: | ----------: |
| 学徒 |   15–25 |   **18–25** |
| 铸师 |   25–40 |   **30–45** |
| 名匠 |   60–90 |   **55–80** |
| 宗师 | 120–180 |  **90–135** |
| 刀圣 | 200–300 | **145–210** |
| 至尊 | 250–400 | **220–320** |

现在从：

`40 → 90 → 180 → 300`

中后期增长过猛。

尤其负重提高的同时，还会同时获得：

* 更高稀有度；
* 更多词缀；
* 更多羁绊；
* 更强特殊刀；
* 更多刀数量；

所以负重增长本身不能再按照“每 +1 斤 ≈ DPS +10%”去设计。当前 Wiki 确实写了这个假设。([GitHub][5])

建议改为：

> **负重自身只贡献约 5–7% 边际战力，剩余成长来自品质和 Build 成型。**

# 十、最后一定要做一个自动数值模拟器

这个项目非常适合做一个很小的 TypeScript balance harness。

完全不需要 Canvas。

输入：

```text
刀阵
敌人
持续时间
玩家移动模型
随机种子
```

跑 1000～10000 次，然后自动输出：

```text
平均 DPS
P10 / P50 / P90 DPS
平均击杀时间
Boss TTK
受到伤害
吸血量
各刀伤害占比
各词缀贡献率
各羁绊贡献率
```

然后准备固定的 5 类测试桩：

| 测试        | 用途        |
| --------- | --------- |
| 单体木桩      | 单体 DPS    |
| 8只低甲怪     | AOE       |
| 100甲重甲怪   | 破甲        |
| 高速怪       | 覆盖        |
| Boss 120秒 | 长线 DoT/吸血 |

最终每次改 Wiki 数字后自动跑。

**以后不是问“镇岳60攻是不是太高”，而是直接看到：**

> 同境界同负重下，镇岳构筑 P50 DPS 比中位 Build 高 28%，其中 17% 来自速度乘区异常。

这才会让这套 Wiki 真正成为你最开始想做的“游戏圣经”。

## 我建议你接下来直接按这个顺序改

**第一刀不是削某把武器，而是：**

> **速度公式 → 羁绊作用域 → 奖励结算 → 声望曲线 → Build 合法性 → 最后才是14把刀面板。**

如果只让我选三个必须优先改的，我会选：

**① 重做速度增伤；② 羁绊改为主系生效；③ 所有金币/刀掉落改为节点结算。**

这三个改完，整个数值体系会稳定一个数量级。然后再做 14 把刀、24 个词缀的逐项精调才有意义。
